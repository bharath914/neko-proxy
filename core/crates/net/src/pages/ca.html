Install the proxy certificate

Your device is talking to a debugging proxy. To read HTTPS traffic, it has to trust this proxy's certificate. It takes about a minute.

Download and install

Use Safari. Other browsers on iPhone can't install profiles.

Download profile
  1. Tap Allow when Safari says the website is trying to download a configuration profile.
  2. Open Settings. Tap Profile Downloaded near the top, or go to General → VPN & Device Management.
  3. Tap the profile, then Install, and enter your passcode.
  4. Then turn on full trust. Without this step, HTTPS still fails: Settings → General → About → Certificate Trust Settings, and switch on the proxy certificate.

Come back to this page. The status above turns green once it works.

Download certificate
  1. Open Settings and search for CA certificate. On most phones it is under Security → Encryption & credentials → Install a certificate.
  2. Choose CA certificate and confirm the warning.
  3. Pick neko-ca.pem from your Downloads.

Android won't install a certificate straight from the browser. It has to go through Settings, as above. Set a screen lock first if you have none.

Apps ignore it by default. Since Android 7, apps only trust certificates you install if their developers allow it. Browsers like Chrome work. For your own app, add this to res/xml/network_security_config.xml in a debug build: 
<network-security-config>
  <debug-overrides>
    <trust-anchors>
      <certificates src="user"/>
    </trust-anchors>
  </debug-overrides>
</network-security-config>
and reference it with android:networkSecurityConfig="@xml/network_security_config" on <application>.
Download certificate

Double-click the file, or install it from Terminal in one step:

sudo security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ~/Downloads/neko-ca.pem

By hand: double-click the file, add it to System in Keychain Access, open it, expand Trust and set Always Trust.

Download certificate
  1. Open the file, choose Install Certificate, then Local Machine.
  2. Choose Place all certificates in the following store and select Trusted Root Certification Authorities.
  3. Finish, and restart your browser.

Or, from an administrator Command Prompt:

certutil -addstore -f Root %USERPROFILE%\Downloads\neko-ca.cer
Download certificate

Pick the line for your distribution. It covers curl, wget, Python, Go and most command-line tools.

Fedora, RHEL

sudo cp ~/Downloads/neko-ca.pem /etc/pki/ca-trust/source/anchors/ && sudo update-ca-trust

Debian, Ubuntu

sudo cp ~/Downloads/neko-ca.pem /usr/local/share/ca-certificates/neko-ca.crt && sudo update-ca-certificates

Arch

sudo trust anchor --store ~/Downloads/neko-ca.pem

Chrome, Chromium and Firefox keep their own store. See the Firefox tab.

Firefox ignores the operating system's certificates by default.

Download certificate
  1. Open about:preferences#privacy, scroll to Certificates and choose View Certificates.
  2. On the Authorities tab choose Import and pick neko-ca.pem.
  3. Tick Trust this CA to identify websites.

On Linux, Chrome and Chromium read the NSS database. Import the same file under Settings → Privacy and security → Manage certificates → Authorities.

What is this?

Why does my device need a certificate?

HTTPS is encrypted from your app to the server. To show you the requests, the proxy has to open that connection, read it, and make a new one to the server. It signs a certificate for each site on the fly, and your device only accepts those if it trusts the authority that signed them. This file is that authority.

Is it safe?

The private key was created on the computer running the proxy and stays there. It never leaves it, and it isn't in the file you download. Anyone holding the key could read your HTTPS traffic, so install this only on devices you are debugging, and remove it when you finish.

Everything is stored locally. Nothing is sent to a server.

What can't it see?

Apps that pin their certificate refuse the proxy's. The proxy notices, passes that traffic through untouched, and flags the connection in the desktop app. Apps that only trust built-in certificates, which includes many Android apps, need the setup shown on the Android tab.

How do I remove it?

iPhone: Settings → General → VPN & Device Management → the profile → Remove Profile.
Android: Settings → Security → Encryption & credentials → Trusted credentials → User → select it and remove.
macOS: Keychain Access → System → delete the proxy certificate.
Windows: run certmgr.msc → Trusted Root Certification Authorities → delete it.
Linux: delete the file you copied, then run update-ca-trust or update-ca-certificates --fresh.

It still says not trusted
  • iPhone: did you switch on full trust under Certificate Trust Settings? Installing alone isn't enough.
  • The proxy line is red: this device isn't using the proxy. Set the Wi-Fi proxy to the address under Proxy above, manual mode, and make sure it is on the same network as the computer.
  • The date is wrong: a device whose clock is off rejects every certificate. Turn on automatic date and time.
  • Firefox: it has its own store. Use the Firefox tab.
  • Only one app fails: it probably pins its certificate or ignores user certificates. Look for it in the desktop app: it shows up flagged.
